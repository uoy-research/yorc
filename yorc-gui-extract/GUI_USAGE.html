YORC Tri-Panel GUI Usage

This guide documents the current desktop registration GUI (yorc-tripanel-gui).

Launch

From repo root:

uv run yorc-tripanel-gui

Launch with inputs prefilled

uv run yorc-tripanel-gui \
  -im /path/to/inside_helmet_mesh.ply \
  -om /path/to/outside_head_mesh.ply \
  -s /path/to/mri_scalp.stl \
  -m /path/to/meg_raw.fif \
  --auto-load

Notes: - -im/--inside-mesh: inside helmet scan (.ply/.stl/.obj/.pcd) - -om/--outside-mesh: outside head scan (.ply/.stl/.obj/.pcd) - -s/--mri-scalp: MRI scalp (.fif/.ply/.stl/.obj) - -m/--megdata: MEG FIF file - If all three mesh paths are provided, load is auto-triggered even without --auto-load. - Renderer can be selected with --renderer auto|native-vtk|pyvista.

Workflow Buttons

  1. Load Data
  2. Pick Inside Fiducials (7)
  3. Pick Outside Anatomy (3)
  4. Pick Inside Face (3)
  5. Pick Outside Face (3)
  6. Pick MRI Face (3)
  7. Compute Transforms
  8. Preview Sensors
  9. Apply to FIF

Extra controls: - Fast Mode: cropped/downsampled ICP for speed - Stabilize ICP: extra ICP rounds until convergence stabilizes - Save Picks / Load Picks: save and restore picked landmarks (JSON) - Show X2 Overlay: inside-to-head alignment overlay - Show X3 Overlay: MRI-to-head alignment overlay - Restore Views: restore base panel rendering after overlays

Picking Controls

Picking is modifier-gated: - Shift + Left Click: add pick point - Shift + Right Click: remove last pick point

Each panel also has: - Confirm Points: confirm currently picked points for that step - Clear Picks: clear picks in that panel - Reset View: clears panel overlays and reloads original loaded geometry for that panel

Current Behavior and Features

  • Meshes are rendered as meshes when available; otherwise point clouds.
  • LIDAR per-vertex colors are preserved when present.
  • Inside/outside path swap is auto-detected from filename patterns and corrected.
  • Compute and preview run in worker threads to keep UI responsive.
  • Registered MRI is shown as semi-transparent mesh when mesh data exists.
  • Sensor preview supports display mode toggle:
    • Display contact points (pad at scalp)
    • Display detector centers (+6 mm)
  • Inside/outside sensor coloring is always based on detector-center position vs scalp mesh:
    • inside = red
    • outside = blue
  • Preview log reports both metrics:
    • median contact-to-scalp distance
    • median detector-to-scalp distance
  • Transform pipeline is rigid-only (rotation + translation). Scale/shear are projected out and rigid diagnostics are logged.

Typical Run (Recommended)

  1. Launch with CLI paths and --auto-load.
  2. Load Picks if you have prior picks.
  3. Verify/correct picks.
  4. Compute Transforms (Fast Mode on first pass).
  5. Preview Sensors.
  6. Switch sensor display mode to inspect contact vs detector geometry.
  7. Use overlays (Show X2, Show X3) for visual QA.
  8. Apply to FIF when satisfied.

Troubleshooting

  • Slow compute: enable Fast Mode, disable Stabilize ICP.
  • Fit quality not stable: enable Stabilize ICP, verify facial/anatomical picks.
  • Many sensors inside scalp:
    • check MRI scalp quality/distortion
    • inspect detector display mode and detector-based inside/outside counts
    • re-pick facial landmarks more consistently
  • GUI rerun hygiene:
    • kill only app-scoped processes (yorc-tripanel-gui)
    • clear only app-specific debug log before relaunch

Sample Data

Sample data is hosted on OSF. Download it by running:

./download_sample_data.sh

This fetches:

  • sampleData/Rxxxx_InHelmet.ply (inside LIDAR)
  • sampleData/Rxxxx_01_Outside.ply (outside LIDAR)
  • sampleData/FS/surf/mriscalp.stl (MRI scalp)
  • sampleData/VEP_DS-raw.fif (MEG recording)

Then launch with all files pre-loaded:

./launch_sample.sh
